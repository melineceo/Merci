# Чего не хватило в договоре (`api.py`)

Договор уже дополнили (`CONTAINER_BUSY`, `retry`, `rename`,
`set_updates`/`show_updates`) — вид всё это поддерживает. Ниже — то, чего
в нём всё ещё нет; сделано в рамках договора, обсудить с ведущим.

## 1. Перетаскивание APK

Приёмник пустой библиотеки говорит «Перетащите APK сюда», но в `Handlers`
нет способа передать логике брошенные файлы. Сейчас вид приём не делает:
он остаётся за логикой (`Gtk.DropTarget` на окне, как в нынешнем
`window.py`). Предлагаемое дополнение:

```python
class Handlers(Protocol):
    def drop_files(self, paths: list[str]) -> None: ...      # брошены файлы

class ShellProtocol(Protocol):
    def set_drop_hover(self, active: bool) -> None: ...      # подсветить приёмник
```

Тогда вид сам повесит приёмник на окно и подсветит библиотеку/приёмник,
пока над ними несут файл.

## 2. Отмена долгой операции

В прототипе варианта 3 у полосы хода была кнопка «Отмена». В договоре
отмены нет, поэтому полоса без кнопки. Если логика умеет отменять:
`SECTION_ACTIONS += ("cancel",)` и `set_stage(text, can_cancel: bool = False)`.

## 3. Чей это ответ

Ответы приходят из потоков, а `show_page` сбрасывает плашку, окна и сборку.
Вид поступает так:

* `show_page` с **другим** приложением, чем показанное сейчас, сбрасывает
  ответы (плашка прячется, окна — «Проверяем окна…», сборка — «проверяем…»,
  правки `set_fact` забываются);
* до первой `show_page` (и после `show_welcome`) ответы сохраняются и
  ложатся на страницу, когда она появится.

Значит, ответы нового приложения логика присылает **после** `show_page`.
Надёжнее было бы передавать ключ записи (`slug`) в `set_build`,
`set_windows`, `set_notice`, `set_fact`, чтобы вид сам отбрасывал
запоздавшие ответы чужого приложения.
